# 基于多Agent与蒙特卡洛树的量化回测与决策系统

> 四川大学 软件学院 · 软件工程专业 2023 级 毕业设计
> 学生：陈奇麟（2023141461037）　指导教师：杨秋辉

输入股票代码或一句自然语言指令，系统自动完成行情获取、因子计算、蒙特卡洛树搜索（MCTS）权重搜索、组合级风控校验，输出带理由的买入/卖出/持有建议。所有中间结果与随机种子留痕，同一输入可复现同一结论。

---

## 1. 设计原则

| 原则 | 含义 |
| --- | --- |
| 强编排，保可复现 | 采用固定拓扑的多 Agent 编排（LangGraph 状态图），不做动态路由。同一输入必然走同一条路径，回测与决策结果可复算。 |
| 决策归代码，解释归 LLM | 买卖方向、目标仓位、风控动作全部由确定性代码与规则引擎产生；大模型只做意图解析和自然语言解释，不参与数值决策。 |
| MVP 优先，增量演进 | 先跑通「在线决策线 + MCTS 工具」主干，再按进度挂载 C++ 回测引擎、离线搜索线、CUDA 加速等组件；做不完的部分作为设计说明写入论文。 |

## 2. 系统架构

两条流水线共用一套数据、因子、回测与权重库底座。

### Workflow 1：在线决策线

```
输入（股票代码 / 自然语言）
  → ① 数据 + 因子 Agent        抓取当日与历史行情，计算基础因子
  → ② MCTS 计算节点            读权重库；未命中则现场搜索最优权重
  → ③ 持仓 + 资金分析 Agent    读取模拟盘状态，计算风险预算
  → ④ 组合级风控                仓位上限 / 单票集中度 / 回撤熔断（硬规则）
  → ⑤ 决策输出 Agent           生成带理由的建议（LLM，只写解释）
  → 决策卡片 + 中间结果 + 决策日志
```

### Workflow 2：离线权重搜索线

```
① 数据检查 Agent    本地是否已有该股近五年数据，缺则补齐
  → ② 搜索空间 Agent          生成因子组合与离散权重组合
  → ③ MCTS 回测 Agent        调用回测引擎做路径模拟与打分
  → ④ 权重库                  高分权重写入 JSON / SQLite
  → （扩展）画图 Agent        权重—收益关系图
```

### 五个层次

| 层次 | 职责 | 目录 |
| --- | --- | --- |
| 数据层 | 行情与财务数据获取、清洗、复权、快照 | `core/data` |
| 因子层 | 因子定义与计算、去极值、标准化、中性化 | `core/factors` |
| 搜索层 | MCTS 与网格、随机基线；搜索器统一接口 | `core/search` |
| 风控层 | 四条硬规则与降级策略 | `core/risk` |
| 解释层 | 结构化模板、本地大模型、数值一致性校验 | `core/explain` |

## 4. 技术栈（规划）

| 用途 | 选型 |
| --- | --- |
| 语言 | Python 3.11 |
| Agent 编排 | LangGraph（固定拓扑状态图） |
| 数据处理 | Pandas、NumPy；本地落地 Parquet + SQLite |
| 行情与财务接口 | 单股工具用 BaoStock 取日线和估值，用 AkShare 取百度总市值和披露财务字段 |
| 回测 | 先向量化实现，后期可替换为 C++ 引擎（插件化） |
| 解释模型 | Ollama 部署 Qwen2.5，本地推理 |
| 服务层 | HTTP + SSE 流式输出 |
| 测试 | pytest |

## 5. 可复现性约定

1. 所有随机过程使用显式种子，配置文件中声明，不接受隐式随机。
2. 行情数据按日期固化快照；同一次实验固定数据版本。
3. 启用权重缓存后，缓存键包括股票代码、数据快照版本、因子和评分规则版本、校准截止日及回测与搜索参数哈希。
4. 每次决策输出附带运行指纹（数据版本、配置哈希、代码版本）与中间结果，可回放。
5. 搜索过程支持中断与续跑，避免长实验因一次失败而重来。

## 7. MVP 实施方案（2026-11 起）

### 7.1 核心目标
跑通**在线决策线（Workflow 1）** 的 6 个固定节点，输入股票代码（如 `600519`）后：
1. 30 秒内输出**结构化决策结果**（买/卖/持 + 因子取值 + MCTS 权重 + 风控状态）；
2. 同一输入连续跑 2 次，**所有字段值完全一致**（可复现性约定落地）；
3. 无任何依赖外部大 Workflow 的耦合代码。

### 7.2 范围边界（每个节点的最小实现）
| 节点位置 | 节点名称 | MVP 最小实现 | 明确不做 |
| --- | --- | --- | --- |
| ① | 意图解析 | 只支持 6 位代码 / `XXXXXX.SH` 格式的解析；自然语言解析留到下一阶段 | 不做模糊匹配、不做多意图、不做实体抽取 |
| ② | Search_Agent（数据+因子） | 五步责任链：`resolve → hot_cache → local_db → fetch_gap → compute_factors`；缓存先做 SQLite（Redis 可选降级）；输出 A–F 六组共 20 列历史因子 | 不做多股并行、不做实时盘中数据、不做因子消融实验 |
| ③ | MCTS 权重节点 | 仅搜索实验配置中指定的组合系数，按 §7.6 计算个股分数和回测收益；搜索预算 1000 rollouts；回测用向量化 Python（先不换 C++） | 不做贝叶斯优化/遗传算法、不做权重库持久化（MVP 阶段每次现场搜）、不做 GPU 加速 |
| ④ | 持仓分析 | 模拟盘用 JSON 文件存状态；只查可用资金、现有仓位 | 不做真实券商 API、不做多账户、不做实时行情持仓同步 |
| ⑤ | 组合风控 | 四条硬规则（仓位上限 80%、单票集中度 30%、回撤熔断 10%、流动性过滤）；触发直接拦截 | 不做 VaR/CVaR、不做压力测试、不做动态阈值 |
| ⑥ | 决策输出 | LLM（Ollama Qwen2.5）只写解释，**不生成决策**；解释必须引用 state 里的数值（防幻觉） | 不做输出模板化、不做多语言、不做历史决策对比解释 |

### 7.3 共享状态字段契约（Workflow 1 内部）
> 节点之间只通过 `state` 字典交换数据，**不直接调用**上/下游节点的函数。

| State 字段 | 类型 | 写入节点 | 读取节点 | 说明 |
| --- | --- | --- | --- | --- |
| `symbol` | `str` | ① | ②③⑤ | 标准代码，如 `600519.SH` |
| `factor_matrix` | `DataFrame` | ② | ③ | 行=交易日，列=20 个因子，按当时已知数据对齐并保留标准化所需历史 |
| `factor_names` | `list[str]` | ② | ③⑥ | 因子列名 |
| `dataset_status` | `str` | ② | ⑤⑥ | `ok`/`partial`/`quarantined` |
| `weights` | `dict[str, float]` | ③ | ⑤⑥ | 启用组合的有效系数（含固定系数和搜索所得系数） |
| `stock_score` | `float \| null` | ③ | ⑤⑥ | 当日最终分（0–100），缺数据时为空 |
| `backtest_score` | `float \| null` | ③ | ⑤⑥ | 所选权重在校准段的年化净收益夏普比率 |
| `portfolio_state` | `dict` | ④ | ⑤ | 可用资金、现有仓位、持仓成本 |
| `risk_result` | `dict` | ⑤ | ⑥ | 风控检查结果：是否通过、触发规则、建议仓位 |
| `decision` | `str` | ⑤ | ⑥ | `buy`/`sell`/`hold` |
| `decision_reason` | `str` | ⑥ | （输出） | LLM 生成的解释 |
| `trace` | `list[dict]` | 所有节点 | （日志） | 每步耗时、命中情况、错误信息 |

### 7.4 验收标准（3 条硬要求）
1. **功能通**：输入 `600519`，30 秒内返回完整 state 字典，所有字段齐全，`decision ∈ {buy, sell, hold}`；
2. **可复现**：连续跑 2 次，`trace` 之外的所有字段**逐值一致**（用固定 seed、固定数据快照、固定搜索预算保证）；
3. **边界稳**：输入不存在的代码 / 新股（上市不足 5 年）/ Redis 挂掉，都能返回带 `status` 的 state，不崩溃。

### 7.5 增量演进路线（MVP 之后）
| 优先级 | 演进项 | 说明 |
| --- | --- | --- |
| P1 | Workflow 2（离线权重搜索线） | 批量搜权重，存权重库，让 Workflow 1 的 MCTS 节点能先查库 |
| P2 | 权重库持久化（SQLite） | MVP 阶段每次现场搜，P2 后把 MCTS 结果存库，命中即跳过 |
| P3 | 回测引擎换 C++ | 插件化替换 Python 向量化回测，加速 MCTS rollout |
| P4 | CUDA 加速 MCTS rollout | GPU 并行路径模拟 |
| P5 | 前端 | 本地 Web 页面展示决策卡片 + 中间结果 |
| P6 | RAG 知识检索 | 检索历史相似行情，给决策输出节点做上下文 |

### 7.6 个股评分计算（MVP）

抓取和评分统一使用 `FACTOR_NAMES` 的 20 个因子，分 A–F 六组。现有代码能够抓取单日快照，20 列历史因子面板和评分尚待实现。评分方案将 20 个因子标准化、定方向后做组内等权平均，组间乘权重后相加。六组有效权重均为正，MCTS 只搜索指定组的系数，其它组用固定系数。标准化用当天之前 40 个完整交易观测，季度财务从公告可用日开始沿用。含 `MOM120` 的当天评分至少需 161 根有效日线，并补齐估值、市值与财务历史。标准化和买卖动画见 [个股评分与 MCTS 系数搜索](docs/project-docs/03-个股评分与MCTS系数搜索.html)。

`最终分 = clip(50 × k + (50 / 3) × S, 0, 100)`，其中 `S` 是六组点积，基准分系数 `k` 的基线为 1。MCTS 可以一起搜权重和 `k`，买卖按未四舍五入的最终分判断。按当前四档权重只搜 A、C 两组，并给 `k` 五档，归一化前有 80 个档位组合。

另设[涨跌预测实验](docs/project-docs/03-个股评分与MCTS系数搜索.html#prediction)。输入同一套 20 个因子，六组分别经过带偏置的非线性神经元，输出上涨概率。MCTS 在校准段比较预测误差，测试段分别报告方向准确度和扣费后的回测表现。
