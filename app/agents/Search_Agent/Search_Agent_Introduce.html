Search Agent 介绍

大 Workflow 中的一个数据节点 · 固定拓扑 · 输入输出走共享 state · 内部用五步责任链实现 · 2026-11-23

先看它在大 Workflow 里的位置——这是定位一切的前提。本模块不是独立对外暴露的 tool，不是 Agent 自主决定何时调用的工具集，也不跨 Workflow 复用。它就是下面这条固定流程里的一环。

这个位置决定了三件事： (1) 它必然被调用——图的结构已经写死了 ①→②→③，不存在"谁决定要不要调"的问题；

(3) 输出写到 state 里，下游 ③ 直接读，不需要再暴露 tool。

本模块只关心 ② Search_Agent 这一个节点的实现。其他节点的职责见项目总 README。

2. 节点契约：输入 / 输出字段

LangGraph 的 state 是一个共享字典，每个节点读写约定好的字段。Search_Agent 的契约如下：

上游必须写（本节点只读，不写）

State 字段类型说明谁写的
symbolstr标准代码，如 600519.SH① 意图解析
data_end_datestrYYYY-MM-DD，默认最近交易日① 意图解析（或 None，本节点填默认）
force_refreshbool忽略缓存重抓（调试用）可选，外部触发写入

本节点必须写（下游会读）

State 字段类型说明谁会读
factor_matrixDataFrame行=交易日，列=20 个因子（已 point-in-time 对齐）③ MCTS 权重节点
factor_nameslist[str]因子列名，如 ["MOM20","VOL20",...]③ MCTS、⑤ 风控
dataset_rangetuple[str,str]实际数据区间，如 ("2021-11-23","2026-11-21")所有下游（做日期对齐）
dataset_statusstrok / partial / quarantined⑤ 风控（状态不为 ok 则降级）
dataset_tracelist[dict]本节点内部责任链每一步的耗时与命中日志、论文测试章节
dataset_warningslist[str]新股不足五年、ST 标记、停牌等⑥ 决策输出（写进解释）
契约即接口。LangGraph 里只要 state 字段对齐，节点内部实现怎么换（比如把责任链换成单个函数），图的装配代码不用动。这就是"依赖倒置"——图依赖的是字段契约，不是节点内部实现。

3. 节点内部实现：五步责任链

节点拿到上游写好的 state 后，内部执行一条固定顺序的责任链。链的每一步都返回"结果 + 耗时 + 状态"，命中就短路，未命中就交给下一步。

1 resolve_symbol 2 hot_cache 3 local_db 4 fetch_gap + validate 5 compute_factors
步骤做什么命中 / 失败判定
① resolve_symbol把 茅台 / 600519 / sh600519 统一成 600519.SH；校验必填字段解析失败 → 节点返回错误 state，不往下走
② hot_cache查 Redis，键 = dataset:{symbol}:{end_date}命中 → 跳过 ③④，直接进 ⑤；未命中 → 继续
③ local_db查 SQLite：覆盖够五年、status = ok、checksum 未变够 → 读库并回填 Redis；不够 → 进抓取
④ fetch_gap + validate只抓缺口（akshare），不复抓已有段；六条校验（价格异常、停牌、涨跌停标记、财务公告日对齐、估值缺失、财务口径）校验不过 → 标 quarantined，不污染正式表
⑤ compute_factors向量化管道就地算 20 个因子；写回库 + Redis；组装 state 字段算失败 → 节点返回错误 state
为什么用责任链：五步依赖的存储层不同（内存 / Redis / SQLite / 网络），失败方式不同（键不存在 vs 区间缺口 vs 数据脏 vs 因子异常）。拆开后每一步能单独测，比如测"校验"时直接喂一份脏数据，不用真联网。这是节点内部的实现细节，LangGraph 和上下游节点都看不到链。

5. 降级与异常处理

节点必须保证要么成功写齐所有输出字段、要么明确报错，不能让下游拿到半套数据。

情况节点行为
新股上市不足五年按实际长度入库，dataset_status = partial，warnings 里写明；因子照样算（窗口不够的列置 NaN，不丢列）
停牌 / 退市数据到截止日，停牌日留行并标记，不截断
接口超时 / 限流重试 3 次（指数退避）；仍失败则返回已有段 + 缺口说明，dataset_status = partial
Redis 挂了跳过步骤 ②，直接查 SQLite；降级不报错，trace 里写明
SQLite 损坏跳过步骤 ③，直接抓口；返回后尝试重建索引
原始数据校验不过不入库，dataset_status = quarantined，warnings 列出异常类型
因子计算报错返回错误 state，dataset_status = error，不写任何因子字段

6. 不做什么

不做理由
不搜权重（不决定是 {0.5,0.3,0.2} 还是别的）下游 ③ MCTS 节点的职责，本节点拿权重反而越界
不做决策（不说买 / 卖 / 持）整个项目都定了"决策归代码"，这是 ⑤⑥ 才有的
不做风控（不查仓位、集中度、熔断）⑤ 风控节点硬规则，放在这里会让节点职责模糊
不生成自然语言解释⑥ 决策输出节点（LLM）职责
不自己决定要不要执行固定拓扑已经写死 ①→②→③，不存在"跳过"这个状态
不暴露独立 tool 给别的图复用本节点只属于这一个 Workflow，字段契约和图结构强绑定
不并行拉多只股票上游意图解析节点决定"一次查几只"，本节点单次只处理一只（并行由图的并发机制控制）
